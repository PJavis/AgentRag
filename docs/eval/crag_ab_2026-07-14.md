## Decision — CRAG_ENABLED = False
Rule: Δsystem ≥ +0.02 AND zero hallucinated on OOC. Measured: Δ = +0.015, hallucinated = 0 → **KEEP OFF**.

CRAG on is **safe** (0/15 hallucinated on the OOC set in the production
configuration — see `refusal_crag_on_2026-07-14.md`) but the correctness gain
(+0.015) is below the +0.02 threshold and inside the judge-noise band
(judge1↔judge2 pearson ≈ 0.94). CRAG flips exactly one row (prod_corpus-27) from
miss to pass (no pass→miss regressions) but does not move the aggregate enough to justify the extra latency of a
critique→corrective-retrieve round-trip. Flag stays `CRAG_ENABLED: bool = False`
in `src/agentrag/config.py`.

## HippoRAG-2 gate verdict — REVISED (2026-07-15): NOT green-lit yet
The first pass read "retrieval_miss dominant (6/9) → build HippoRAG-2." A per-row
re-audit rejects that: **most misses are broken eval questions, not system failures.**

Of the 9 misses, 6 are unanswerable-by-design synthetic questions — dangling
demonstratives with no antecedent or meta-references to the source artifact:

| qid | bucket | question | defect |
|---|---|---|---|
| prod_corpus-0  | generation_miss | "…môn học **này**…" | dangling "này" |
| prod_corpus-14 | generation_miss | "…bệnh nhân **này**…" | dangling "này" |
| prod_corpus-5  | retrieval_miss  | "câu 8 đến câu 12 trong **đề thi**" | meta |
| prod_corpus-16 | retrieval_miss  | "câu hỏi số 18 đến 21 trong **đề thi**" | meta |
| prod_corpus-38 | retrieval_miss  | "câu hỏi nào trong **đoạn văn**" | meta |
| prod_corpus-39 | retrieval_miss  | "**đoạn văn này** chứa câu hỏi gì" | dangling + meta |

On these, oracle scores ~1.0 only because it is handed the gold context; the system
scores 0 because the standalone question has no anchor to retrieve on. No graph or
reranker closes that — the question itself is broken. This is the same class as the
v3 landmine: the eval set inflates oracle−system with fake headroom.

**Genuine system misses: ~3**, none a clean retrieval-coverage zero —
prod_corpus-21 (sys 0.39, partial answer), prod_corpus-26 (sys 0.43, partial),
prod_corpus-27 (false abstention: gold packed, rerank 0.72, LLM refused; the one row
CRAG rescued). That is too thin, and too generation/abstention-flavoured, to justify
a HippoRAG-2 build.

**→ Next build: eval-set question-quality filter, THEN re-measure.** Added
`src/agentrag/eval/question_quality.py` (flags dangling-demonstrative + meta-artifact
questions) and wired it into `build_prod_evalset.py`. Rebuild `c2_evalset_n40.jsonl`
with the filter, re-run the CRAG-off probe, and read the CLEAN headroom + bucket
split. HippoRAG-2 (`docs/superpowers/specs/2026-07-14-hipporag2-structmem-design.md`)
stays GATED on that clean run showing `retrieval_miss` still dominant among *real*
questions.

## Notes
- **Row-dump content bug found + fixed mid-run.** `build_probe_row` dumped passage
  text under key `content`, but production `packed_context` stores it under
  `excerpt` (context.py `_stage_citation_pack`). Every packed passage in the dump
  was therefore empty, which forced `gold_overlap`=0.00 on every row — so the FIRST
  bucket pass misclassified all 7 non-abstention misses as `retrieval_miss` (hiding
  2 real generation_miss) and citation mining yielded 0 triplets. The existing
  `test_build_probe_row_shape` masked the bug by using the wrong (`content`) key in
  its fixture. Fixed (`excerpt`→`content` normalisation) + regression test; both
  arms re-run clean. Post-fix: 294/294 packed passages carry content, 44 citation
  triplets mined.
- Retrieval misses cluster on context-dependent queries with no anchor terms
  ("Tài liệu học tập của môn học **này**", "câu hỏi từ câu 8 đến 12 trong đề thi",
  "mô học xương đùi của bệnh nhân **này**") — the retriever has nothing to key on.
- judge-noise pearson: 0.942 (off) / 0.944 (on) — healthy, >0.9.
- oracle avg differs slightly between arms (0.911 vs 0.902) despite identical gold
  context + oracle model = LLM sampling noise; consistent with Δsystem sitting in
  the noise band.
- judge-disagreement rows (|sys−judge2| ≥ 0.4): prod_corpus-23, -30 (off); -23 (on).
