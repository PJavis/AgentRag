## Decision — CRAG_ENABLED = False
Rule: Δsystem ≥ +0.02 AND zero hallucinated on OOC. Measured: Δ = +0.015, hallucinated = 0 → **KEEP OFF**.

CRAG on is **safe** (0/15 hallucinated on the OOC set in the production
configuration — see `refusal_crag_on_2026-07-14.md`) but the correctness gain
(+0.015) is below the +0.02 threshold and inside the judge-noise band
(judge1↔judge2 pearson ≈ 0.94). CRAG flips exactly one row (prod_corpus-27) from
miss to pass (no pass→miss regressions) but does not move the aggregate enough to justify the extra latency of a
critique→corrective-retrieve round-trip. Flag stays `CRAG_ENABLED: bool = False`
in `src/agentrag/config.py`.

## HippoRAG-2 gate verdict
Dominant bucket: **retrieval_miss** (6 of 9 misses, CRAG off; still 5 of 8 with CRAG on).
The gold chunk never reaches the answer LLM on these — a corrective-retrieve round
(CRAG) does not fix it, confirming the failure is retrieval coverage, not a
re-query. → next build: **write the HippoRAG-2 StructMem/graph spec**
(`docs/superpowers/specs/2026-07-14-hipporag2-structmem-design.md`).

The 2 generation_miss rows (prod_corpus-0, prod_corpus-14) have gold_overlap=1.00 —
gold was packed, answer still scored 0 → answer-prompt territory, tracked separately,
not part of the HippoRAG gate.

## Notes
- **Row-dump content bug found + fixed mid-run.** `build_probe_row` dumped passage
  text under key `content`, but production `packed_context` stores it under
  `excerpt` (context.py `_stage_citation_pack`). Every packed passage in the dump
  was therefore empty, which forced `gold_overlap`=0.00 on every row — so the FIRST
  bucket pass misclassified all 7 non-abstention misses as `retrieval_miss` (hiding
  2 real generation_miss) and citation mining yielded 0 triplets. The existing
  `test_build_probe_row_shape` masked the bug by using the wrong (`content`) key in
  its fixture. Fixed (`excerpt`→`content` normalisation) + regression test; both
  arms re-run clean. Post-fix: 294/294 packed passages carry content, 44 citation
  triplets mined.
- Retrieval misses cluster on context-dependent queries with no anchor terms
  ("Tài liệu học tập của môn học **này**", "câu hỏi từ câu 8 đến 12 trong đề thi",
  "mô học xương đùi của bệnh nhân **này**") — the retriever has nothing to key on.
- judge-noise pearson: 0.942 (off) / 0.944 (on) — healthy, >0.9.
- oracle avg differs slightly between arms (0.911 vs 0.902) despite identical gold
  context + oracle model = LLM sampling noise; consistent with Δsystem sitting in
  the noise band.
- judge-disagreement rows (|sys−judge2| ≥ 0.4): prod_corpus-23, -30 (off); -23 (on).
