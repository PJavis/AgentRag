# HyDE on/off A/B — 2026-07-17 (config reconciliation before merge)

The whole campaign's eval config ran with HyDE **on** (`.env QUERY_REWRITE_ENABLED=true`,
via `KnowledgeService.bootstrap_search`), but `config.py` shipped the default **off**
(`QUERY_REWRITE_ENABLED: bool = False`). So the validated numbers didn't match the prod
default. A/B'd it on the clean set to settle the shipped default.

Eval set `c2_evalset_n40_clean_v2.jsonl` (41 rows, CRAG off, rerank-before-trim + breadth active):

| config | system avg | oracle−system | misses | judge-noise |
|---|---|---|---|---|
| HyDE **on** (validated) | **0.904** | +0.044 | 23, multihop-6 | 0.86 |
| HyDE **off** | 0.864 | +0.038 | 23, **28**, multihop-6, **multihop-9** | 0.91 |

- **Δ = −0.039** with HyDE off, **2 pass→miss regressions** (prod_corpus-28, multihop-9),
  0 recovered. HyDE contributes a real ~+0.04 on the clean set.
- Fails the pre-registered ship-off bar (HyDE-off ≥ 0.894). 

## Decision — ship HyDE ON
Set `config.py QUERY_REWRITE_ENABLED: bool = True` so the shipped default matches the
validated eval config. HyDE-on was already the config for every campaign probe and passed the
OOC refusal gate (15/15 abstain, 0 hallucinated), so enabling it in prod carries no new OOC
risk. Cost: one extra (cheap) LLM call per query for the hypothetical — justified by +0.04.

The branch (PR #6) is now config-clean: rerank-before-trim + breadth + HyDE-on are all in
`config.py`, matching the measured 0.884→0.904 numbers.
