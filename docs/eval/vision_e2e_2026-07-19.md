# Vision Slice C — answer-time vision e2e A/B (2026-07-19)

**Question:** Now that gemini image captions are in the retrieval index (Phase 2), does turning
**answer-time** vision ON (`VISION_ANSWER_MODEL=gemini-2.5-flash`, the answer model reads the actual
image pixels) improve end-to-end answer correctness vs OFF (text-only, captions still retrievable)?

**Method:** `scripts/eval/run_vision_e2e_ab.py` over `data/eval/vision_evalset_2026-07-19.jsonl`
(40 synthesized **image-dependent** questions, text-answerable ones filtered out). Same agent, same
retrieval; the only change is `VISION_ANSWER_MODEL` (`""` = OFF vs `gemini-2.5-flash` = ON), set on
the settings singleton at runtime (env `VISION_ANSWER_MODEL=""` is a no-op — `config.py`
`env_ignore_empty=True`). Correctness graded by the project's ensemble judge (`score_correctness`,
`.mean` 0–1).

## Result

| arm | VISION_ANSWER_MODEL | n | scored | mean correctness |
|---|---|---|---|---|
| OFF | `""` | 40 | 40 | **0.4104** |
| ON  | `gemini-2.5-flash` | 40 | 40 | **0.3868** |

**Delta (ON − OFF) = −0.0236.** Pre-registered decision rule: default-ON iff delta ≥ +0.03.
**→ NOT met. Keep answer-time vision OFF** (the Slice-A default already ships OFF).

Per-question (Δ threshold ±0.05): **4 helped, 4 hurt, 32 ≈unchanged** (one "unchanged" is a
trivial +0.02). The net is a wash, within the judge's noise band.

### Where vision helped (read diagram detail the caption missed)
- *"how many distinct effects … in the central diagram"* — 0.50 → 1.00
- *"how many distinct lettered sub-points listed under …"* — 0.50 → 1.00
- *"what inflammatory tissue is proliferating …"* — 0.14 → 0.50
- *"name of the labelled structure …"* — 0.57 → 0.75

### Where vision hurt (mis-counted / mis-read vs the text caption)
- *"how many distinct medical signs are illustrated"* — 1.00 → 0.00
- *"how many pictorial representations of vitamin D sources"* — 1.00 → 0.50
- *"how many distinct colored rectangular blocks"* — 0.50 → 0.00
- *"which C1 structure is fractured"* — 1.00 → 0.50

The wins are real visual reads; the losses are gemini mis-counting/mis-identifying image elements
worse than the retrieved caption already stated. They cancel.

## Why the effect is small (important caveats)

1. **Retrieval surfaces an image for only ~9–14 of 40 questions.** The answer node only goes
   multimodal when `packed_context` contains an image segment (`images=4` logged for 9 questions in
   the OFF run, 14 in the ON run — retrieval is nondeterministic run-to-run). For the other ~26–31
   questions both arms are text-only by construction, so ≥65% of the set cannot move. Caption-based
   retrieval does not reliably rank the *right* image for a visual-detail question (the caption
   describes content, not "how many asterisks"). This caps any achievable lift and is the real
   bottleneck — not the answer model.
2. **Small N + judge noise.** 40 questions, ensemble-judge noise ~±0.2/question; a ±0.024 aggregate
   delta is indistinguishable from zero.
3. **Synthesized eval-set limits.** Questions were gemini-drafted with a text-answerability filter
   (hardened v2). No human gold; some questions test trivial visual counts that are legitimately
   ambiguous.

## Verdict / recommendation

**Keep answer-time vision default-OFF.** On the current corpus + eval it does not improve
correctness (−0.024, noise). The captions themselves are in the index and retrievable (that value
stands); paying for a vision model at answer time is not justified yet.

**The lever with headroom is retrieval, not the answer model:** images surface for only ~1/3 of
image-dependent questions. Before revisiting answer-time vision, improve image-segment retrieval
(e.g. CLIP visual embeddings — already schema-supported but disabled here; or caption enrichment so
visual-detail queries rank the right figure). Re-run this exact A/B after that.
